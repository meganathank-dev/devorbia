# 🔐 Authentication & Security

We'll build the authentication system using:

* Password hashing
* Access/refresh authentication architecture
* HTTP-only cookies
* Authentication middleware
* RBAC middleware
* Tenant authorization
* Resource-level authorization
* Zod validation
* Secure CORS
* Security headers
* Rate limiting
* Request-size limits
* Centralized error handling
* Environment variables

We won't add an external authentication service unless there is a genuine need.

# 🤖 AI Layer

This is an important part of DevOrbia.

We should **not tightly couple the application to a single paid AI provider**.

We'll create an internal AI abstraction:

```text
DevOrbia
    ↓
AI Service Layer
    ↓
AI Provider Interface
    ↓
┌──────────────────────┐
│ Free / Local AI      │
│ Development Provider │
│ Future AI Provider   │
└──────────────────────┘
```

The five AI capabilities:

### 1. AI Resource Assignment

Skills + workload + availability + experience + deadlines + project familiarity.

### 2. AI Project Risk & Health Detection

Progress + overdue tasks + blocked tasks + dependencies + workload + deadlines.

### 3. AI Workload Balancing

Employee/team capacity + assignments + deadlines + skills.

### 4. Leave Impact + Smart Reassignment

Leave + affected tasks + deadlines + dependencies + team capacity.

### 5. Performance & Recognition Intelligence

Completion + timeliness + complexity + consistency + contribution + improvement.

The **core scoring/analysis can be implemented locally**, while an AI model can be used where natural-language reasoning or explanations add value.

### 🎯 The important decision

I would **not add Next.js, TypeScript, Redux, PostgreSQL, Firebase, Supabase, Docker, microservices, Kubernetes, or other technologies just because they are popular**.

Your finalized stack is already more than sufficient to build a serious full-stack project.

**MERN + Tailwind + Zustand + Zod + AI abstraction + proper security + testing** is the right level of complexity for DevOrbia.
