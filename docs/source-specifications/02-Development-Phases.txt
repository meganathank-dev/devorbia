# DevOrbia — Complete Project Building Phases

This document defines the **official development roadmap** for building DevOrbia phase by phase.

The project must **not be built completely in one step**. Each phase should be implemented, tested, verified, and stabilized before moving to the next phase.

---

# Phase 0 — Project Foundation & Architecture

### Goal

Create the complete technical foundation without implementing major business features.

### Backend

* Initialize Node.js project
* Configure Express.js
* Configure MongoDB + Mongoose
* Configure environment variables
* Configure Zod
* Configure ESLint/formatting
* Create API versioning: `/api/v1`
* Create centralized configuration
* Create centralized error handling foundation
* Create logging foundation
* Create health-check API
* Establish layered architecture:

  * Routes
  * Controllers
  * Services
  * Repositories
  * Models
  * Middleware
  * Validators
  * Utilities

### Frontend

* Initialize React + Vite
* Configure Tailwind CSS v4
* Configure React Router
* Configure Zustand
* Configure Axios
* Configure Lucide React
* Create application layout foundation
* Create sidebar
* Create header
* Create responsive layout
* Create reusable UI components
* Create loading, error and empty-state components

### Testing

* Basic backend test setup
* Basic frontend test setup
* Health API test

### Documentation

Create:

* README
* Environment documentation
* Architecture documentation
* API conventions
* Development commands

### Expected Result

A clean MERN project skeleton that runs successfully on both frontend and backend.

**No major business functionality yet.**

# Phase 2 — Organization & Multi-Tenancy

This is one of the **most critical phases** of DevOrbia.

---

## Phase 2A — Organization Management

### Super Admin functionality

Implement:

* Create organization
* View organizations
* Edit organization
* Activate organization
* Deactivate organization
* Organization statistics
* Manage organization access

### Important Rule

Super Admin operates at the **DevOrbia platform level**.

Super Admin does **not** participate in the internal management hierarchy of organizations.

For example:

Super Admin does not approve an organization's employee leave.

---

# Phase 2B — Multi-Tenant Architecture

Implement organization isolation throughout the backend.

### Rules

Organization-owned resources must contain an organization reference.

Examples:

```text
Employee → organizationId
Department → organizationId
Team → organizationId
Project → organizationId
Task → organizationId
```

### Secure Query Pattern

Avoid:

```text
find project by projectId
```

Prefer:

```text
find project by projectId + authenticated organizationId
```

### Implement

* Tenant middleware/context
* Organization-scoped repositories
* Organization authorization
* Resource ownership validation
* Cross-tenant protection

### Critical Test

User from Organization A attempts to access Organization B's project.

Expected:

**Access denied / resource not found.**

Organization B data must never be returned.

# Phase 8 — Deadline & Project Progress Intelligence

Before implementing advanced AI, establish reliable non-AI calculations.

### Implement

* Task completion percentage
* Project completion percentage
* Overdue task detection
* Upcoming deadline detection
* Project deadline status
* Task priority analysis
* Active/completed task counts

### Example

If:

```text
100 total tasks
80 completed
```

Project task completion:

**80%**

### Delayed/Overdue

If:

```text
Due date < Current date
AND
Task is not Done
```

then task becomes:

**Overdue / Delayed**

This data becomes the foundation for later AI features.

# 🚨 Most Important Development Rule

**Do NOT ask Antigravity IDE to build all 26 phases at once.**

For each phase:

```text
Understand current project
        ↓
Inspect existing files
        ↓
Plan the phase
        ↓
Implement only that phase
        ↓
Run the application
        ↓
Test the phase
        ↓
Fix issues
        ↓
Verify existing features still work
        ↓
Document completion
        ↓
Move to next phase
```

### AI features must come after the core platform.

The correct order is:

**Reliable data → Reliable business logic → Reliable analytics → AI intelligence**

not:

**AI first → build the actual application later.**

This approach will keep DevOrbia **secure, maintainable, testable, and realistic enough for a final-year project and portfolio-level demonstration.**
